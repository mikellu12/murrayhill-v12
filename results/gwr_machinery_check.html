GWR Machinery Check

The revised section adds an ε offset, AICc bandwidth search, the hat matrix, a sandwich variance, node-level t-statistics and an FDR correction. Most of it does not touch t_base — the hat matrix and the shape of the standard errors are functions of the predictors and the kernel alone — so it is checkable now even though the regression is not runnable.

Two things that do not line up

  • n = 1,320 is not this frame. The paper states 1,320 nodes on a sidewalk dual-discretization network — 660 × 2. This frame produces 2,724 half-views from 681 nodes. The FDR correction is applied over n, so every localized p-value threshold depends on which is right.
  • |t| ≥ 2.65 is an outcome, not a threshold. The arithmetic is correct — two-sided p at 2.65 is 0.0080 — but under Benjamini-Hochberg the critical value is k·α/m for the largest passing rank k. It is computed from the fitted p-values, not fixed before the fit.

2.65 is the BH threshold only if about 211 of 1,320 nodes come out significant — roughly 16% of the map non-stationary. On 2,724 nodes the same count gives 2.89. Stating the threshold in advance assumes the answer.

What is still blocked

Only the outcome. t_base is still specified as “public data feeds and computer-vision sensor nodes”, and the draft's own limitations section concedes the calibration “remains dependent on a static temporal snapshot of pedestrian activity”. Queried live, NYC Open Data has 0 automated pedestrian sensors within 1 km and 1 manual count site inside the frame — and both measure flow past a point, not time spent at it.

Everything else is ready. The predictors are separable (VIF 1.60), the solve is stable, the hat matrix is well behaved, and 150 m is a sensible starting bandwidth. The moment stayability counts exist for even a sample of nodes, this runs.
